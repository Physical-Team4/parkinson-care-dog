# MechDog 포트 전압 및 GPIO 출력 검증 기록

## 1. 기록 범위와 근거

- 시험일: 2026-11-26
- 시험·결과 제공: B 담당자
- 목적: 포트의 DC 전위차와 Port 3의 GPIO32·GPIO33 무부하 출력 동작 확인
- 장비: Hiwonder MechDog Advanced Kit, GN-5100 디지털 멀티미터, Thonny
- 기록 기준: B 담당자가 전달한 측정 결과와 작업 설명. 문서 작성 과정에서 장비 시험을 새로 실행하지 않았다.
- 추가 확인: B 담당자가 GPIO33도 HIGH에서 LOW로 복귀한 뒤 멀티미터로 0V를 확인했다고 보고하여 반영했다.
- 비교한 저장소 기준: `origin/main`의 `e44ddab` (2026-11-26).
- 후속 문서 확인: `origin/main`의 `919a11c`에서 D의 터치 센서 GPIO33 확인이 추가됐다. 아래 5.2절에 출처와 시험 범위의 차이를 구분한다.
- 상태: 상세 실측 기록. 제조사 공식 핀맵 또는 팀 공통 핀맵의 확정·변경 문서가 아니다.

이 문서는 [핀맵](../pinmap.md), [하드웨어 구성](../hardware.md), [미확정 항목](../todo.md)과 함께 읽는다.
공식 핀맵 대조, 후보 GND의 기준 검증, 허용 전류, 신호 기능은 확인 범위가 서로 다르다.
전압 측정만으로 센서·레이저 연결 적합성이나 허용 전류를 확인한 것으로 해석하지 않는다.

## 2. 시험 조건과 핀 번호 기준

### 2.1 확인된 조건

- 내부 포트, Port 2, Port 3을 DC 전압 모드로 측정하고 재측정했다.
- 내부 포트는 검은색 프로브를 임시 2번 핀에 고정했다.
- Port 2와 Port 3은 검은색 프로브를 임시 3번 핀에 고정했다.
- Port 3 GPIO 출력 시험 중 레이저와 외부 센서는 연결하지 않았다. 출력 시험은 무부하 조건이다.
- GPIO 출력 모드는 Thonny Shell에서 MicroPython `machine.Pin`으로 임시 설정했다.

### 2.2 임시 번호와 관찰 방향의 한계

이 문서의 1~4번은 **측정자가 당시 커넥터를 바라본 방향에서 정한 임시 번호**다.
제조사 핀 번호, Raspberry Pi의 물리 핀 번호 또는 GPIO 번호가 아니다.
각 포트에서 임시 번호와 GPIO의 대응은 별도로 확인해야 한다.

**당시 관찰 방향의 사진·도식은 아직 제공되지 않았다.** 보드 쪽/케이블 쪽, 잠금턱 방향,
왼쪽/오른쪽을 이 문서에서 임의로 정하지 않는다. 다른 팀원은 숫자만 보고 핀을 선택하면 안 된다.
시험을 재현하기 전에 원래 측정자와 다음을 확인하고 사진에 번호를 표시해야 한다.

| 포트 | 기존 측정의 검은색 프로브 위치 | 추가로 필요한 식별 정보 |
|---|---|---|
| 내부 포트 | 임시 2번 | 보드 내 위치, 커넥터 종류, 관찰 방향, 1~4번 사진 |
| Port 2 | 임시 3번 | 포트 표기와 잠금턱 방향이 함께 보이는 1~4번 사진 |
| Port 3 | 임시 3번 | 포트 표기와 잠금턱 방향이 함께 보이는 1~4번 사진 |

특히 **‘내부 포트’가 정확히 어떤 커넥터인지 미확인**이다.
팀 규칙은 NC·+·− 배터리 3핀 및 UART로 추정되는 빈 4핀 커넥터 사용을 금지한다.
기존 측정 사실은 남기지만, 내부 포트는 해당 금지 커넥터와의 관계 및 공식 자료를 확인하기 전에는
추가 시험·배선 대상으로 삼지 않는다. 이 기록은 금지 커넥터 사용을 허용하지 않는다.

### 2.3 보고되지 않은 조건

- 보드·펌웨어의 정확한 버전, Thonny 버전
- 시험 당시 전원 공급 경로와 배터리 잔량
- 멀티미터 렌지, 정확도·교정 상태, 프로브 접촉 사진
- 최초 측정과 재측정의 개별 원자료, 반복 횟수·시간
- 전체 부착 모듈 목록과 내장 라이브러리의 GPIO 사용 상태

위 항목은 재시험 때 기록한다. 다른 장비의 조건이나 저장소의 예정 구성을 이번 시험 조건으로 채우지 않는다.

## 3. DC 전압 측정과 재측정 결과

### 3.1 최초 측정·재측정의 구분

제공된 설명에는 최초 측정 후 GND 후보에 검은색 프로브를 고정하여 재측정했고,
결과의 재현성을 확인했다고 보고되어 있다.
다만 최초와 재측정이 분리된 수치 목록 및 최초 프로브 배치의 상세 원자료는 제공되지 않았다.
따라서 아래 표는 **전달받은 최종 측정값**이며, 동일 수치를 두 개의 독립 측정 기록으로 복제하지 않는다.

| 단계 | 보고된 사실 | 별도 수치 원자료 |
|---|---|---|
| 최초 DC 전압 측정 | 세 포트를 측정함. Port 3 신호 두 핀에서 50~200mV 변동 관찰 | 단계별 표 미제공 |
| GND 후보 기준 재측정 | 내부는 임시 2번, Port 2·3은 임시 3번에 검은색 프로브 고정. 재현성 확인 보고 | 아래 통합 표로 제공, 최초와 분리된 표 미제공 |

### 3.2 전달받은 최종 전압 표

전압은 각 포트에서 고정한 검은색 프로브에 대한 빨간색 프로브의 전위차다.
GND 후보 행은 기준 프로브 위치를 뜻하며, 별도 0.00V 측정값을 보고받은 것으로 기록하지 않는다.

| 임시 핀 | 내부 포트 | Port 2 | Port 3 |
|---|---|---|---|
| 1번 | 5.08V | 3.62V | 50~200mV 변동 |
| 2번 | GND 후보: 기준 프로브 | 3.62V | 50~200mV 변동 |
| 3번 | 3.62V | GND 후보: 기준 프로브 | GND 후보: 기준 프로브 |
| 4번 | 3.62V | 5.08V | 5.08V |

**측정 사실:** 세 포트에서 각각 5.08V의 안정적인 전위차를 확인했고, 재측정의 재현성이 보고됐다.

**후보·해석:** 내부 1번과 Port 2·3의 4번은 5V 전원 후보다.
기준으로 사용한 핀은 GND 후보이며 공식 핀맵 또는 확인된 보드 GND와의 대조가 필요하다.
3.62V라는 DC 값만으로 신호 핀의 허용 전압·로직 규격·통신 기능을 확정하지 않는다.
특히 Port 2의 두 신호 중 SDA/SCL 순서는 미검증이다.

## 4. Port 3 GPIO 출력 시험

### 4.1 방법과 관찰

초기 Port 3의 신호 두 핀에서는 50~200mV 변동이 관찰됐다.
외부 센서와 레이저를 연결하지 않은 상태에서 GPIO32와 GPIO33을 각각 출력 모드로 설정하고,
LOW → HIGH → LOW 순서로 설정하며 멀티미터로 전압을 확인했다.
검은색 프로브는 Port 3 임시 3번 GND 후보에 고정했다.

| 항목 | GPIO32 | GPIO33 |
|---|---|---|
| 대응하는 Port 3 임시 핀 | 1번 | 2번 |
| 출력 설정 전 | 50~200mV 변동 | 50~200mV 변동 |
| LOW 출력 실측 | 0V | 0V |
| HIGH 출력 실측 | 3.31V | 3.35V |
| 마지막 LOW 복귀 | 0V 실측 확인 | 0V 실측 확인 (추가 확인 반영) |

**검증된 범위:** Port 3 임시 1번은 GPIO32, 임시 2번은 GPIO33 출력 변화에 대응했다.
두 GPIO 모두 무부하 상태에서 LOW → HIGH → LOW 전환을 실측으로 확인했으며,
무부하 디지털 출력 제어 검증을 완료했다. GPIO32와 GPIO33의 마지막 LOW 복귀 전압은 모두 0V다.
레이저 연결 또는 부하가 걸린 상태에서의 출력 제어까지 검증한 것은 아니다.

**추정:** 초기 변동은 GPIO 초기 설정 상태와 관련됐을 가능성이 있다.
입력 모드·풀업/풀다운·기존 프로그램 영향은 직접 확인하지 않았으므로 원인을 확정하지 않는다.
초기 변동만으로 포트 고장이라고 판단할 근거는 없다.

### 4.2 MicroPython 명령어: 재현용 재구성 예시

실제 시험에서 `machine.Pin`을 이용해 출력 모드와 LOW/HIGH를 설정했다는 설명을 제공받았다.
**당시 Shell 입력 전문은 미제공**이므로 다음은 같은 시험을 재현하기 위해 재구성한 예시다.
당시 변수명·입력 순서·출력 로그를 그대로 복원한 기록 또는 새로 실행한 결과가 아니다.

외부 장치를 분리하고 핀 대응·기존 프로그램의 GPIO 점유 여부를 확인한 뒤,
Thonny Shell에서 **한 줄씩** 실행한다. HIGH 상태를 유지한 채 다음 줄을 자동 실행하지 말고
각 단계의 실측값을 별도로 기록한다. `Pin.value()` 조회는 소프트웨어 상태이며 멀티미터 실측을 대신하지 않는다.

GPIO32 (Port 3 임시 1번):

```python
from machine import Pin
p32 = Pin(32, Pin.OUT, value=0)
# LOW 전압 측정 및 기록
p32.value(1)
# HIGH 전압 측정 및 기록
p32.value(0)
# LOW 복귀 전압 측정 및 기록
```

GPIO33 (Port 3 임시 2번):

```python
p33 = Pin(33, Pin.OUT, value=0)
# LOW 전압 측정 및 기록
p33.value(1)
# HIGH 전압 측정 및 기록
p33.value(0)
# LOW 복귀 전압 측정 및 기록 (기존 시험에서 0V 실측 확인)
```

종료 시, 두 변수가 정의된 상태에서 LOW를 다시 설정한다.

```python
p32.value(0)
p33.value(0)
```

이 예시는 파일 저장·펌웨어 변경·GPIO 상태의 영구 설정을 하지 않는다.
재부팅 이후 GPIO 상태나 내장 라이브러리의 재설정 여부는 별도 확인 대상이다.

## 5. 실측 기반 Port 3 핀맵과 기존 문서 비교

### 5.1 임시 핀맵

**원래 관찰 방향을 확인한 경우에만 유효하다.** 제조사 공식 핀맵으로 전환하지 않는다.

| Port 3 임시 핀 | 역할 | 근거와 상태 |
|---|---|---|
| 1번 | GPIO32 | LOW 0V → HIGH 3.31V → LOW 0V 실측 |
| 2번 | GPIO33 | LOW 0V → HIGH 3.35V → LOW 0V 실측 |
| 3번 | GND 후보 | 검은색 프로브 기준. 보드 GND와의 독립 대조 미검증 |
| 4번 | 5V 전원 후보 | 임시 3번 기준 5.08V. 허용 전류 미검증 |

GPIO 출력은 약 3.3V이며, 임시 4번의 5V 전원 후보와 다르다.
GPIO가 5V 입력을 허용하거나 레이저 전력을 직접 공급할 수 있다는 뜻이 아니다.

### 5.2 `docs/pinmap.md`와 비교

다음 표의 기존 문서 열은 최초 비교 기준 `e44ddab`을 따른다.

| 항목 | 기존 문서 | 이번 기록 | 판단 |
|---|---|---|---|
| Port 3 신호 | IO32, IO33 | 임시 1번↔GPIO32, 2번↔GPIO33 | GPIO 구성은 일치. 방향 확인이 필요한 물리 대응 정보 추가 |
| Port 3 전원·GND 순서 | 확정된 순서 없음. TODO에 핀 순서·VCC 전압 확인 필요 | 임시 3번 GND 후보, 4번 5.08V 후보 | 실측 근거 추가. 공식 순서 확정은 아님 |
| 터치 IO | IO32/IO33 중 실제 사용 핀 미확정 | 터치 동작·간접 점유 여부 미검증 | 미확정 유지 |
| Port 2 | IIC1, MP3 배정 | 두 신호 3.62V, 임시 4번 5.08V | 버스 번호·SDA/SCL 기능을 전압만으로 검증하지 못함 |
| 내부 포트 | 내장 초음파 IIC1 및 사용 금지 빈 4핀 항목 존재 | 위치 식별 미완료 | 어느 항목인지 대응시킬 수 없음. 추가 연결 보류 |
| 레이저 핀·연결 | 미확정 | 레이저 미연결 | 미확정 유지 |

현재 제공된 범위에서 Port 3 GPIO 구성의 직접적인 모순은 발견되지 않았다.
사진·공식 자료가 없어 전체 물리 핀 순서의 일치까지 확인한 것은 아니다.
**이번 문서 작업은 `docs/pinmap.md`, 설정 코드 또는 팀의 확정 규칙을 변경하지 않는다.**

**후속 확인 (2026-11-26, `919a11c`):** [D의 터치 센서 변경 PR #13](https://github.com/Physical-Team4/parkinson-care-dog/pull/13)과
[해당 커밋의 핀맵](https://github.com/Physical-Team4/parkinson-care-dog/blob/919a11c2afc0263323fb48023b2d1083b061b971/docs/pinmap.md)은
터치 핀을 **GPIO33**, 입력 `PULL_UP`, 누름=0 / 뗌=1로 기록한다.
이는 B가 수행한 무부하 출력 시험과 다른 시험의 결과다. B의 이번 시험에서 터치 동작을 검증한 것으로 합치지 않는다.
터치 센서가 연결되거나 관련 서비스가 실행 중일 때 GPIO33을 출력 모드로 바꾸는 재시험은 하지 않는다.
레이저용 IO와 Port 3의 허용 전류는 여전히 미확정이다.

## 6. 기존 ESP32 환경과 변경 여부

다음은 Thonny에서 확인했다고 제공된 정보다.

- 보드 파일: `main.py`, `boot.py`.
- 기존 `main.py`: 제조사 블루투스 앱 제어 코드, 약 359줄.
- 주요 내장 모듈: `Hiwonder`, `Hiwonder_IIC`, `Hiwonder_ADC`, `Hiwonder_BLE`,
  `HW_MechDog`, `MechDog`, `machine`, `ledMatrix`, `uart_ctl`, `WonderCam`.
- 제조사 라이브러리는 펌웨어에 내장되어 있다.
- 기존 코드에서 다음 구성을 확인했다.

```python
i2c1 = Hiwonder_IIC.IIC(1)
i2csonar = Hiwonder_IIC.I2CSonar(i2c1)
```

기존 코드에서 GPIO32·GPIO33의 직접 제어는 발견되지 않았다고 보고됐다.
그러나 내장 라이브러리가 간접적으로 해당 핀을 사용하는지는 완전히 검증하지 않았다.

시험은 Thonny Shell에서 임시 실행했으며 다음 사항을 보고받았다.

- `main.py`, `boot.py` 수정 없음.
- 펌웨어 재설치·공장 초기화 없음.
- 종료 시 GPIO32·GPIO33을 LOW로 설정하고 두 핀 모두 멀티미터로 0V를 확인한 뒤 연결 해제 절차 진행.

기존 파일의 별도 백업 완료 여부와 파일 해시 비교 결과는 미제공이다.
‘파일을 수정하지 않음’을 ‘백업을 완료함’ 또는 ‘GPIO 초기 상태까지 완전히 복원함’으로 기록하지 않는다.

## 7. 팀원 재시험 절차

아래는 후속 재시험 방법이다. 아직 수행하지 않은 단계는 완료 기록이 아니다.
내부 포트는 2.2절의 식별·금지 여부 확인 전에는 제외한다.

1. 원래 측정자와 커넥터 관찰 방향·임시 번호를 사진으로 대조한다. 대응이 불명확하면 시험을 멈춘다.
2. 레이저·외부 센서가 분리된 상태인지 확인한다. 분리·배선 변경은 전원을 끈 상태에서 한다.
   기존 연결 상태는 먼저 사진으로 남긴다. 보드 밑면을 금속 표면에 놓지 않는다.
3. 전원 공급 경로·보드 상태·계측기 설정을 기록한다. 모터 제어 명령·블루투스 조작을 시험에 섞지 않는다.
   제조사 부팅 코드 자체의 동작 가능성을 확인하고 안전하게 고정한다.
4. GN-5100 설명서의 단자 표기에 따라 검은색 리드는 COM, 빨간색 리드는 전압 측정 단자에 꽂고 DC 전압 모드를 사용한다.
   전류 단자·전류 모드로 전원 핀과 GND 사이를 측정하지 않는다.
5. 포트별 GND 후보를 확인하고 검은색 프로브를 고정한 뒤, 빨간색 프로브로 각 핀을 하나씩 측정한다.
   프로브가 인접 핀을 동시에 건드리지 않도록 한다. 전원이 켜진 보드에서 저항·도통 측정은 하지 않는다.
6. 최초 측정표와 재측정표를 따로 작성한다. 변동값은 단일 숫자로 바꾸지 말고 범위·관찰 시간을 남긴다.
7. Port 3 출력 시험 전 기존 프로그램이 중단되어 Thonny Shell을 사용할 수 있는지와 GPIO 점유를 확인한다.
   진행 중인 코드와 핀이 충돌할 수 있으면 출력 시험을 보류한다.
   자동 실행을 다시 유발할 수 있는 리셋·Ctrl-D를 재현 단계에 포함하지 않는다.
8. 4.2절을 참고해 GPIO32·33을 각각 한 단계씩 설정하고 LOW/HIGH/LOW 전압을 별도로 기록한다.
   `Hiwonder`, `MechDog` 등 모션 객체를 생성하거나 팀의 `esp32/main.py`를 실행하지 않는다.
9. 마지막에 두 핀을 LOW로 설정하고 각각 전압을 확인한다. 프로그램을 장치 파일로 저장하지 않는다.
   안전하게 종료한 뒤 전원을 분리하고 연결 상태를 정리한다.

재시험용 기록 형식:

| 시험자·시각 | 포트·사진 식별자 | 관찰 방향·핀 | 전원 조건 | 검은색 프로브 기준 | GPIO 설정 | 최초 전압 | 재측정 전압 | 마지막 LOW 실측 | 비고 |
|---|---|---|---|---|---|---|---|---|---|
| 미실시 | | | | | | | | | |

## 8. 검증 완료 범위와 미검증 사항

### 8.1 제공된 결과로 확인된 범위

- 세 포트에서 각 기준 프로브에 대한 5.08V의 안정적 전위차 및 재측정 재현성 보고.
- Port 3의 임시 1번↔GPIO32, 임시 2번↔GPIO33 대응과 두 GPIO의 무부하 디지털 출력 제어 검증 완료.
- GPIO32 HIGH 3.31V, GPIO33 HIGH 3.35V, 각각의 최초 LOW 0V.
- GPIO32·GPIO33 모두 LOW → HIGH → LOW 전환 및 마지막 LOW 복귀 0V 실측 확인.
- 기존 `main.py`·`boot.py`를 수정하지 않고 Shell에서 시험했다는 보고.

### 8.2 아직 확인하지 않은 항목

- 관찰 방향 사진, 제조사 공식 핀 번호와의 대응, GND 후보의 독립 대조.
- 내부 포트의 정확한 식별과 사용 금지 커넥터 해당 여부.
- Port 2 SDA/SCL 순서, 신호 파형 및 통신 동작.
- 각 포트·GPIO의 허용 전류 및 부하 연결 시 전압·발열.
- 실제 레이저 연결 및 부하 상태에서의 출력 제어.
- B의 이번 시험에서는 터치 동작을 검증하지 않았다. D의 별도 GPIO33 확인은 5.2절 참고.
- 내장 라이브러리의 GPIO32·33 사용 여부.
- 레이저 모듈의 허용 전압, 소비 전류, 3.3V 제어 신호 호환성, 안전 등급.
- 전압 측정 당시 조건의 전체 기록 및 원본 Shell 로그.
- 기존 ESP32 파일의 별도 백업 완료 여부.

### 8.3 레이저·외부 센서 연결 전 조건

- 공식 핀맵·관찰 방향과 전원/GND를 먼저 대조한다.
- 모듈 데이터시트에서 전압·소비 전류·제어 신호와 보드의 허용 전류를 확인한다.
- Port 2의 SDA/SCL, Port 3의 기존 점유 핀을 확인하기 전에는 연결하지 않는다.
- GPIO 출력을 5V 전원 대용으로 쓰거나, GPIO에 5V 전원을 연결하지 않는다.
- 무부하 출력 시험 결과만으로 모듈 직결을 결정하지 않는다.
- 레이저는 별도 승인된 연결 시험에서만 다루며 기본 꺼짐·바닥 방향 원칙을 따른다.
- 미확정 값을 설정 코드에 채우거나 기존 핀맵을 자동 변경하지 않는다.

## 9. USB 시리얼과의 관계 및 후속 작업

이번 전압·GPIO 시험은 USB 시리얼 송수신 시험과 별개다.
이전 사용자 보고에는 Pi USB-A↔MechDog USB-C 연결 시 CH340(`1a86:7523`),
`/dev/ttyUSB0`, 사용자 `dialout` 권한 확인이 있다. 이 문서 작성 시 해당 장치 상태를 재조회하지 않았다.

| 항목 | 상태 |
|---|---|
| USB 장치 인식 | 이전 보고에서 확인. 다음 시험에서 재확인 필요 |
| 이번 포트 전압·GPIO 시험 | 위 표에 보고된 범위에서 확인 |
| Pi → ESP32 애플리케이션 데이터 | 아직 검증하지 않음 |
| ESP32 → Pi 애플리케이션 데이터 | 아직 검증하지 않음 |
| JSON·명령 ID·ACK·응답 시간·반복 안정성 | 아직 검증하지 않음 |
| Heartbeat 및 타임아웃 | 아직 검증하지 않음 |

후속 통신 시험은 [시리얼 프로토콜 초안 v0](../serial-protocol.md)와
[ESP32 규칙](../../esp32/CLAUDE.md)을 기준으로 B·D(필요 시 C)가 합의한다.
USB 시리얼은 REPL과 포트를 공유한다. Thonny와 Pi 앱의 동시 점유,
DTR/RTS에 의한 리셋, Ctrl-C/Ctrl-D에 의한 실행 상태 변화를 확인해야 한다.

팀 `esp32/main.py`는 보행 객체 초기화 과정에서 모터를 제어할 수 있으므로
무동작 통신 시험용으로 그대로 실행하지 않는다. 기존 파일을 보존하면서
모터·레이저를 초기화하지 않는 시험 방법을 먼저 검토한다.

## 10. 팀원 공유용 요약

2026-11-26, MechDog 내부 포트·Port 2·Port 3의 전압을 측정·재측정했고 각 기준 핀에 대해
5.08V의 안정적 전위차를 확인했습니다. Port 3은 측정 당시 임시 번호 기준
1번=GPIO32, 2번=GPIO33으로 대응했으며, 무부하 HIGH가 각각 3.31V·3.35V,
최초 LOW와 HIGH에서 복귀한 마지막 LOW는 두 GPIO 모두 0V로 실측 확인했습니다.
GPIO32·GPIO33 모두 LOW → HIGH → LOW 전환을 확인하여 무부하 디지털 출력 제어 검증을 완료했습니다.
기존 main.py·boot.py와 펌웨어는 수정하지 않았습니다.
관찰 방향 사진·공식 핀맵 대조, GND·5V 후보 확정, 허용 전류,
실제 레이저 연결·호환성, 부하 상태의 출력 제어와 Pi↔ESP32 양방향 데이터 통신은 별도 검증이 필요합니다.
D는 별도 시험에서 터치를 GPIO33 입력으로 확인했으며, B의 무부하 출력 시험과 구분해 기록했습니다.
