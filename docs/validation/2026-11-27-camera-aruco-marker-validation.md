# 실제 카메라 및 ArUco 마커 인식 검증

- 문서 작성일: 2026-11-27
- 시험·결과 제공: B 담당자
- 목적: #24(M1 마커 인식)의 남은 항목 "Pi 카메라로 실제 마커 인식, 인식 시간 확인"을 실제 장비로 확인하고,
  [navigation.md](../navigation.md) §11-③ 마커 인식 거리 실측의 1차 관측값을 남긴다
- 기록 근거: B 담당자가 제공한 시험 조건, 관측 결과, 집계 수치
- 문서 작성 기준: `origin/main`의 `fdcea61`
- 변경 범위: 검증 기록만 추가. 코드·`.env`는 바꾸지 않았고, 문서 작성 과정에서 측정을 다시 하지 않았다.

**결론:** Hailo 없이 실제 Camera Module 3 프레임에서 CPU 기반 OpenCV ArUco 마커 인식이 동작하고,
마커의 좌우 위치(가로 위치)도 방향에 맞게 출력된다. 대표 측정에서 50·100·200cm는 100% 인식, 300cm는 0%였다.
다만 모니터 표시·카메라 수동 지지 조건의 단발 측정이며, 같은 거리에서도 회차에 따라 인식률이 크게 달랐다.
**이 결과로 최대 인식 거리, 보장 인식률, `CAMERA_FOCAL_PX`를 확정하지 않는다.**

이 측정은 기존 `pi/scripts/marker_test.py` 단독 실행 결과다.
`pose_viewer --markers-only` 뷰어와 터미널 동시 측정(#38)으로 잰 값이 아니다.

## 1. 시험 환경

| 항목 | 시험 당시 조건 |
|---|---|
| Raspberry Pi | Raspberry Pi 5 8GB (AI HAT+/Hailo 사용 안 함) |
| 카메라 | Camera Module 3 (IMX708) |
| Python 환경 | Conda `pd-dog` |
| 카메라 라이브러리 | Picamera2 + libcamera (conda 환경에서 사용) |
| 마커 인식 | OpenCV `cv2.aruco`, CPU |

### 카메라 확인 결과

| 확인 항목 | 결과 |
|---|---|
| Camera Module 3 (IMX708) 인식 | 정상 |
| Conda 환경에서 Picamera2·libcamera | 정상 작동 |
| 실제 카메라 프레임 캡처 | 640×480×3 `uint8` 성공 |
| Hailo 없이 CPU 기반 ArUco 마커 인식 | 성공 |

카메라 초기화 때 V4L2 `Nc30`, `Nc12` 관련 경고가 출력됐으나, 실제 캡처와 마커 인식은 동작했다.
경고의 원인과 영향은 확인하지 않았다.

## 2. 실험 조건

| 항목 | 조건 |
|---|---|
| 측정 도구 | 기존 `pi/scripts/marker_test.py` (단독 실행) |
| ArUco 사전 | `DICT_4X4_50` |
| 목표 마커 ID | 1 |
| 마커 검은 사각형 한 변 | 15cm |
| 마커 표시 방식 | **모니터 화면 표시** (인쇄물 아님) |
| 카메라 해상도 | 640×480 |
| 처리 | CPU |
| 카메라 고정 | **수동 지지 (Handheld)** |
| 준비 시간 | 3초 |
| 측정 시간 | 10초 |

초점거리 추정(px) = 마커 한 변(px) × 거리(cm) ÷ 마커 크기(cm) (`marker_test.py` 계산식).

## 3. 거리별 관측 결과 (대표 측정)

| 거리 | 인식률 | 인식 프레임 | 마커 한 변 (px) | 초점거리 추정 (px) | 처리 시간 중앙값 (ms) | 최대 (ms) |
|---|---|---|---|---|---|---|
| 50cm | 100% | 293/293 | 252.3 | 841 | 2.7 | 13.8 |
| 100cm | 100% | 293/293 | 138.0 | 920 | 3.9 | 14.6 |
| 150cm | 미측정 | — | — | — | — | — |
| 200cm | 100% | 293/293 | 92.3 | 1230 | 4.2 | 15.2 |
| 250cm | 보류 | — | — | — | — | — |
| 300cm | 0% | 0/293 | — | — | 3.5 | 13.5 |
| 400cm | 미측정 | — | — | — | — | — |

- 대표 결과는 카메라 방향을 안정시킨 뒤 다시 잰 회차다. **반복 측정의 평균이 아니다.**
- 250cm는 인쇄물을 준비한 뒤 측정하기로 해 보류했다.
- 400cm는 실내 공간과 케이블 길이 제한으로 측정하지 않았다.
- 마커 인식 처리 시간은 모든 회차에서 중앙값 2.7~4.2ms, 최대 15.2ms 이하였다 (§8 "마커 인식 수 ms/프레임"과 맞음).

## 4. 좌우 위치별 관측 결과 (100cm)

| 위치 | 가로 위치 | 인식률 | 인식 프레임 | 마커 한 변 (px) | 처리 시간 중앙값 (ms) | 최대 (ms) |
|---|---|---|---|---|---|---|
| 왼쪽 | -0.39 | 100% | 293/293 | 174.3 | 3.3 | 14.3 |
| 중앙 | +0.08 | 100% | 293/293 | 138.0 | 3.9 | 14.6 |
| 오른쪽 | +0.51 | 100% | 293/293 | 160.4 | 4.4 | 15.1 |

- 마커를 왼쪽·오른쪽에 두었을 때 가로 위치 부호가 맞게 바뀌어, 마커 방향(bearing) 정보가 정상 출력됨을 확인했다.
- 같은 100cm인데도 위치에 따라 한 변이 138.0~174.3px로 달랐다. 수동 지지에 따른 실제 거리·각도 차이일 수 있으나 원인은 확인하지 않았다.

## 5. 추가 관측

**인식률이 회차마다 크게 달랐다.**

| 회차 | 50cm | 100cm | 200cm |
|---|---|---|---|
| 초기 측정 | 75% | 87% | 73% |
| 재측정 중 한 회차 | 0% | 77% | — |
| 대표 측정 (§3) | 100% | 100% | 100% |

- 카메라 이동 시간, 흔들림, 촬영 각도 불일치의 영향으로 추정하지만 원인은 확정하지 않았다.

**목표 외 ID 오인식이 있었다.**
- 100cm 정면, 100cm 오른쪽, 300cm 측정에서 목표 외 ID 17이 각각 1회 검출됐다.
- 길찾기에 쓰기 전에 목표 ID 필터링, 연속 프레임 확인 같은 안전장치를 검토해야 한다.

**초점거리는 확정하지 않았다.**
- 거리별 초점거리 추정값이 841~1230px로 편차가 크다. 따라서 `CAMERA_FOCAL_PX`는 정하지 않았고 `.env`에도 넣지 않았다.
- 이 값은 B 장비(카메라·마커) 기준이다. A 로봇의 `.env`에는 A 장비로 잰 값을 넣는다.
