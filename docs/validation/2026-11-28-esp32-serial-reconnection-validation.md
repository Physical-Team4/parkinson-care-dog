# ESP32 시리얼 끊김·재연결 실기기 검증 (T3 재검증)

- 시험일: 2026-11-28 (17:12–17:41, 시각은 모두 Pi 현지 시각 KST)
- 시험·조작: B 담당자 / 로그 정리: Claude Code
- 목적: [PR #42 검증 기록](https://github.com/Physical-Team4/parkinson-care-dog/pull/42) T3에서 발견한 "ESP32 USB 분리 시 Pi 앱 종료" 수정이 실제 Pi·MechDog에서 동작하는지 확인
- 시험 코드: Pi `fix/esp32-serial-reconnection` `49b4042`, ESP32는 T1에서 업로드한 main 코드(`6f80917`, 이후 `1cf6d6b`까지 `esp32/` 변경 없음)
- 기록 근거: Pi `~/measure-logs/`의 앱 로그(`t3b-app-1712.log`, `t3b-start-disconnected-1733.log`), 상태 감시 로그(`t3b-watch-*.log`, 1초마다 `robot_latest`·미확인 알람 읽기), 커널 로그(`dmesg`), `medication_logs`·`alerts` 조회(읽기만)
- 변경 범위: 검증 기록만 추가. 시험 중 기존 코드·ESP32 펌웨어·DB 설정·`.env`는 수정하지 않았다. 공유 DB에는 시험으로 생긴 데이터만 있다 (7절).

**결론:** USB 분리·MechDog 전원 종료에도 Pi 앱이 종료되지 않았고, 끊긴 동안 `esp32_ok=false`(ESP32 값은 비움)와 Pi 상태 보고가 계속됐다.
ttyUSB0가 다시 잡히면 자동으로 복구되고 설정·시계가 다시 전송됐다. MechDog를 연결하지 않은 채 앱을 시작해도 종료되지 않고 연결 후 복구됐다.
끊긴 상태에서 `top`으로 한 번 잰 앱 CPU는 0.0%였다 (단일 측정, 장시간 평균·최대는 미측정). 후속 문제 3건(충전기 없이 `charging` 표시, 통신 끊김 시 보행 안전 정지 없음, 끊긴 동안 Pi→ESP32 메시지 유실)은 8절에 정리한다.

## 5. 시험 중 관찰 (수정 대상 아님)

- **재연결 때 ESP32 리셋**: 포트를 다시 열 때 ESP32가 처음부터 시작하는 것으로 보인다 (T1 `POWERON_RESET`, 이번에는 복구 직후 복약 알림 재시작). 설정·시계는 자동으로 다시 전송되므로 기능상 문제는 없었다.
- **충전기 없이 `mode=charging`**: 17:31:35부터 17:41:34(감시 끝)까지 `charging` (17:39:01–17:39:03만 `medication`). 시험 중 MechDog 충전기는 연결하지 않았다. 17:17:12에는 `idle`이었고, 17:26:53–17:31:35는 감시 로그가 없다. 터치 센서 장착·전원 재시작 뒤부터 관측됐으나 관계는 확인하지 않았다 → 8절 후속.

## 8. 후속 이슈 (이번 PR에서 수정하지 않음)

1. **MechDog 충전기 없이 `charging` 표시** (D): 5절. [PR #42](https://github.com/Physical-Team4/parkinson-care-dog/pull/42) "MechDog 충전 감지"(충전기 연결해도 `idle`)와 반대 증상. `esp32/drivers/battery.py`의 외부 전원 판정을 실측 전압과 함께 확인 필요.
2. **Pi ↔ ESP32 통신이 끊겨도 ESP32 보행이 멈추지 않음** (C·D): ESP32는 `hb` 5초 끊김 시 `pi_alive()=false`로 알람만 현장 소리로 바꾸고 `rhythm`은 계속한다. USB만 빠지고 MechDog 전원이 켜져 있으면 걷던 동작이 계속될 수 있다. 펌웨어 쪽 정지 규칙(또는 이동 명령 TTL, [navigation.md](../navigation.md)) 필요.
3. **끊긴 동안 Pi → ESP32 메시지 유실** (B·D): `med_ack`·`pi_low`·`shutdown`·`settings`는 대기열 없이 버린다 (재연결 뒤 예전 `walk` 등이 늦게 실행되지 않도록 한 의도된 동작). `settings`는 재연결 때 다시 보내고, `shutdown`은 ESP32의 `hb` 5초 끊김 판단으로 대체된다. 음성 복약 확인(`med_ack`)을 구현할 때 재전송 여부를 정해야 한다.
