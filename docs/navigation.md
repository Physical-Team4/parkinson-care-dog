# 로봇 이동 설계 (마커 길찾기 + 사람 중심 이동)

> **상태: 설계 초안 (2026-11-27, 담당 A).** 시리얼 메시지(§6)는 C·D와 합의 전 **제안**이다.
> 확정되면 [serial-protocol.md](serial-protocol.md)에 옮기고, 결정은 [decisions.md](decisions.md) D-012에 기록한다.

## 1. 목적과 범위
- 로봇이 집 안에서 **목적지(방)까지 이동**하고, 도착하면 **사람을 찾아 F6·F7로 지켜볼 수 있는 자리**를 잡는다.
- 하지 않는 것: SLAM·지도 작성, 정밀 위치 추정, 계단·문턱 넘기, 문 열기.
- 이유: 작은 4족 로봇(MechDog) + Pi 5에서 라이다·SLAM은 무겁고, 바닥이 자주 바뀌는 집에서는 **마커(ArUco)** 몇 개로 길목만 알려주는 편이 단순하고 확실하다.

## 2. 전체 구조

```
[집 지도 = 마커 연결표 (설정 파일)]
  1(거실 입구) ─ 2(복도) ─ 3(안방 입구)
                   └─ 4(부엌 입구)          10(잠자리 마커, 안방)

Pi (A)                                          ESP32 (C·D)
 카메라 프레임 ─┬─ 마커 인식 (OpenCV, CPU)        걷기 move(보폭 mm, 각도 °)
               └─ pose (Hailo) → F6·F7          앞 초음파: 장애물 즉시 정지 (안전 반사)
 경로 계산 (연결표, BFS)                         IMU 기울기: 넘어짐 → 정지 (방향은 IMU 없음)
 이동 상태 머신 ── nav_move / nav_stop ──────────▶ 명령 유효시간(TTL) 지나면 스스로 정지
                ◀── status(front_cm, mode) · nav_blocked ──
 방향은 마커를 보며 바로잡는다 (IMU에 yaw가 없음)
```

**나눈 이유**
- **Pi**: 카메라를 보고 판단해야 하는 일 (마커·사람 인식, 경로, 상태 전환).
- **ESP32**: 늦으면 위험한 일 (장애물 정지, 넘어짐, 명령 끊김 시 정지). Pi가 멈추거나 시리얼이 끊겨도 로봇이 계속 걸어가지 않게 한다.

## 3. 하드웨어 전제와 미확정 값 (M0에서 실측)

| 항목 | 현재 알고 있는 것 | 확인할 것 |
|---|---|---|
| 걷기 | `move(보폭 mm -100~100, 각도 -30~30°, 양수=왼쪽)` 계속 걷기, `move(0,0)` 정지 (위키 확인, [mechdog-motion.md](mechdog-motion.md)). **제자리 회전 API 없음**, 공식 시리얼 이동 명령도 전진/후진 회전 8종뿐 | **제자리 회전 가능 여부**: `move(0, 각도)`, `move(1, 30)`(보폭 1mm ≈ 제자리걸음). 회전 속도(°/s), 직진 속도(cm/s), 범위 밖 각도(±40 등) 처리 |
| 앞 초음파 | IIC1 0x77. Python `getDistance()`는 예제상 cm, 공식 시리얼 `CMD|4|1|$`는 mm (위키, [mechdog-sonar.md](mechdog-sonar.md)) | Python 값의 실제 단위·최대 거리, 낮은 장애물(문턱·전선) 감지 여부 |
| IMU | `Hiwonder_IIC.MPU().read_angle()` → **기울기(X·Y)만**. 자이로·yaw API 없음 (위키) | 넘어짐 판단 기울기 임계값 (`robot_tipped`) |
| 배터리 | 공식 시리얼 `CMD|6|$`는 mV. 2S 기준 6.4V=0%, 8.4V=100% 변환 | Python에서 전압 읽는 API |
| 카메라 | 카메라 모듈 3(일반형), 거꾸로 장착(`CAMERA_HFLIP/VFLIP`), 640×480 | 장착 높이·숙임 각도, 화각(공식 사양 확인), 마커 인식 최대 거리 |
| 마커 | — | 크기(예: 10~15cm), 붙이는 높이, 조명·밤 인식 |
| 밤 | 일반 카메라는 어두우면 마커·사람 모두 못 봄 | NoIR·조명 결정 ([todo.md](todo.md)) |

미확정 값은 코드에 넣지 않고 `pi/app/config.py`(Pi)·`esp32/config.py`(ESP32)에서 읽는다. 값이 없으면 해당 기능을 끈다.
위키의 `CMD|...|$` 명령은 **공식 슬레이브 UART 프로토콜이라 사용 금지**([esp32/CLAUDE.md](../esp32/CLAUDE.md)). 단위 참고용으로만 적었고,
보드에서는 Python API(`move`, `I2CSonar`, `MPU`)를 쓴다.

## 4. 마커
- 종류: **ArUco `DICT_4X4_50`** (작고 인식이 잘 되는 기본 사전). 인쇄해서 벽 아래쪽(로봇 카메라 높이)에 붙인다.
- 마커 하나 = 번호 하나. 용도:
  - **길목 마커**: 방 입구·복도 등 경로의 점.
  - **잠자리 마커**: 요를 펴는 자리 머리맡 (F6 "발견 시 이미 누움" 판단, [features.md](features.md)).
  - (나중) 충전 자리 마커.
- 인식: Pi CPU에서 OpenCV `cv2.aruco`. **pose와 같은 프레임**을 쓰고 처리 후 바로 버린다 (영상 저장 금지 그대로).
- 마커에서 얻는 값: 화면 가로 위치 → **방향(bearing)**, 화면상 크기 → **대략적인 거리**. 처음에는 카메라 보정(calibration) 없이 이 두 값만 쓴다.

## 5. 집 지도 = 마커 연결표 (설정 파일)
- 집마다 다르므로 레포에는 **예시 파일만** 둔다: `pi/config/home_map.example.yaml` (구현 때 추가). 실제 파일은 Pi 로컬(`~/pd-dog-data/home_map.yaml`).
- 방 이름 정도라 민감 정보는 아니지만, 집 구조라서 Supabase에는 올리지 않는다.

```yaml
markers:
  1:  {name: 거실 입구, room: living}
  2:  {name: 복도}
  3:  {name: 안방 입구, room: bedroom}
  4:  {name: 부엌 입구, room: kitchen}
  10: {name: 잠자리, type: sleep_spot, room: bedroom}
edges:                    # 서로 이어진 길목. turn: 앞 마커에 도착한 뒤 다음 마커를 찾으려면 어느 쪽으로 돌지 (힌트)
  - {from: 1, to: 2, turn: right}
  - {from: 2, to: 3, turn: left}
  - {from: 2, to: 4, turn: right}
rooms:                    # 목적지 이름 → 도착 기준 마커
  living: 1
  bedroom: 3
  kitchen: 4
```
- 경로: 연결표에서 너비 우선 탐색(BFS). 마커가 수십 개 이하라 계산 부담 없음.
- `turn` 힌트가 없으면 제자리에서 돌며 찾는다 (느리지만 동작).

## 6. 시리얼 메시지 (제안 — C·D 합의 전)
기존 `walk`(F3 박자 보행)·`stop`과 섞이지 않게 `nav_` 접두사를 쓴다. **`stop`은 이동도 멈춘다** (어떤 상황에서든 "멈춰" 한 번으로 정지).

**Pi → ESP32**

| t | 필드 | 설명 |
|---|---|---|
| `nav_move` | `stride` (mm, -100~100, 앞+), `angle` (°, -30~30, **왼쪽+**, `move()`와 같은 부호), `ttl_ms` | `move(stride, angle)`로 걷기. **ttl_ms 안에 다음 명령이 없으면 ESP32가 스스로 정지**. Pi는 약 5~10Hz로 다시 보냄. ESP32는 범위를 잘라서(clamp) 쓴다 |
| `nav_stop` | — | 이동만 정지 (F3에는 영향 없음) |

- **`nav_turn`(각도만큼 회전)은 빼기로 함**: IMU에 yaw가 없어 ESP32가 몇 도 돌았는지 알 수 없다.
  회전은 Pi가 `nav_move`로 하면서 **마커 위치로 확인**하고, 마커가 없을 때는 M0에서 잰 회전 속도(°/s)로 시간을 계산한다.

**ESP32 → Pi**

| t | 필드 | 설명 |
|---|---|---|
| `status` (기존) | + `front_cm` | 앞 초음파 거리(**cm**, ESP32가 단위 변환). `mode`에 `navigating` 추가 |
| `nav_blocked` | `front_cm` | 앞 장애물로 스스로 정지함 |

**ESP32 안전 규칙 (Pi와 상관없이 항상)**
- 앞 초음파 < `NAV_STOP_CM` → 즉시 `move(0,0)` + `nav_blocked`.
- `ttl_ms` 지남, Pi 하트비트 끊김(`PI_TIMEOUT_MS`), 넘어짐(`robot_tipped`, IMU 기울기) → 정지.
- F3 박자 보행 중에는 `nav_*` 거절 (`ack ok:false err:"busy"`). 우선순위: `stop` > 경보 > F3 > 이동.

**Pi 쪽 영향**
- `pi/app/config.py`의 `robot_moving_modes`에 `navigating` 추가 → 이동 중 F7 누적 멈춤 (F6는 계속, 흔들림 영향은 실측).

## 7. 이동 상태 머신 (Pi)

```
IDLE ──목적지 요청──▶ LOCATE ──마커 보임──▶ ALIGN ──가운데 맞춤──▶ APPROACH ──충분히 가까움──▶ 다음 마커?
  ▲                    │ 안 보이면 돌며 찾기                                            ├─ 있음 → TURN_NEXT → LOCATE
  │                    └─ 시간 초과 → FAILED                                             └─ 없음 → ARRIVED
  │
  └── WATCH ◀── APPROACH_PERSON ◀── SEARCH_PERSON ◀── ARRIVED
       (정지, F6·F7)  (2~3m 거리로)    (돌며 pose로 사람 찾기)
```
- **ALIGN/APPROACH**: 마커의 화면 가로 위치로 `w`(회전)를, 크기로 `v`(전진)를 정한다. 마커를 놓치면 멈추고 LOCATE로.
- **APPROACH_PERSON**: 사람 bbox 높이를 거리 대용으로 써서 **2~3m**에 선다 (F6·F7 판정 거리, [features.md](features.md)). 너무 가까이 가지 않는다.
- **WATCH**: 정지 상태 → F7 누적이 동작한다. 사람이 화면 밖으로 나가면 SEARCH_PERSON.
- **중단 조건**: 음성 "멈춰"·`stop`, F6 낙상 의심(즉시 정지 후 지켜보기), F3 시작, 배터리 부족, `nav_blocked`가 계속됨 → 정지하고 `status`로 알림.
- 목적지 요청 경로(음성 "안방 가자", 대시보드, 시간표)는 B·D와 협의.

## 10. 미확정·위험
- 제자리 회전이 안 되면 회전은 `move(작은 보폭, 각도)`로 작은 원을 그리며 해야 한다 → 좁은 복도에서 불리.
- IMU에 yaw가 없어 방향을 직접 알 수 없다 → 직진·회전 모두 **마커를 보며** 바로잡는다. 마커가 안 보이는 구간은 짧게 잡는다.
- 낮은 장애물(전선·문턱·러그 끝)은 초음파가 못 볼 수 있다 → 실측 후 경로에서 피하거나 마커 위치 조정.
- 바닥 재질(미끄러운 마루·러그)에 따라 걸음·회전량이 달라진다.
- 밤에는 마커·사람 모두 인식이 어렵다 → 밤 카메라 결정 전까지 밤 이동은 하지 않는다.
