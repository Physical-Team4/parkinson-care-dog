# 기능과 모델

| ID | 기능 | 방법 | 처리 위치 | 담당 |
|---|---|---|---|---|
| F1 | 복약 알림 | 타이머 + 터치 (AI 없음). 30분 미확인 시 보호자 알림 | ESP32 (알림 전송은 Pi) | D |
| F2 | 위급 신고 | 터치 3초 / "도와줘" 음성 | ESP32 + Pi | D (+B 음성) |
| F3 | 리듬 큐잉 보행 | 박자 타이머 + "출발/걷자", "멈춰". 80~110 BPM. MP3 박자음 + 레이저 깜빡임. ToF로 사용자가 멀어지면 대기 | ESP32 (보행·박자) + Pi (음성) | C (+B 음성) |
| F4 | 발성 훈련 | RMS → dB (numpy). 서보 정지 상태에서 측정 | Pi | B |
| F5 | 사용자 인식 | ECAPA-TDNN (약 80MB) | Pi | B |
| F6 | 낙상 감지 | YOLO pose 키포인트 + 규칙. 모델은 Hailo-8L 벤치마크로 선택 (n에 한정 안 함, 입력 640) ([아래](#f6f7-비전-계획)) | Pi + AI HAT+ | A |
| F7 | 무움직임 확인 | F6와 같은 포즈 결과 + 규칙 (추가 모델·학습 없음) | Pi + AI HAT+ | A |
| 공통 | 음성 명령 | Silero VAD + Vosk 한국어 small | Pi | B |

## 공통 원칙
- 영상은 저장·전송하지 않음 (실시간 처리 후 폐기). 대시보드에는 키포인트만 Realtime Broadcast로 보냄 (저장 안 함).
- 음성 원본은 저장하지 않음. 화자 임베딩은 Pi 로컬에만 (Supabase에 올리지 않음).
- 음성 인식·dB 측정은 서보가 멈춘 상태에서 (모터 소음 때문).
- 레이저는 기본 꺼짐, 바닥만 향하게 (눈 높이 금지).

## 알림 흐름
- 위급(빨강): 낙상(camera), 무움직임(no_motion), 터치 신고(touch), 음성 신고(voice)
- 주의(주황): 복약 미확인(medication_missed), 배터리 부족, 로봇 넘어짐
- 보호자 원격 알림은 Pi 동작 중에만. Pi 무응답이면 ESP32가 MP3 경보음.
- 인터넷이 끊기면 알람·기록은 Pi 대기열에 쌓였다가 연결되면 Supabase로 재전송 ([db.md](db.md#오프라인-대기열-pi)).

## F6·F7 비전 계획
담당 A. 코드: `pi/app/services/vision/` (판정), `pi/app/adapters/hailo.py`·`camera.py` (추론·캡처).
결정 기록: [decisions.md](decisions.md) D-009(Hailo 사용), D-010(모델 선택 방식). 벤치마크: [benchmarks.md](benchmarks.md).

### 구조
```
카메라 프레임 → Hailo pose 추론 → 사람 bbox + COCO 17 키포인트 → 프레임 즉시 폐기
   ├─ 0.4초마다 키포인트·상태 → Realtime Broadcast (저장 안 함, docs/api.md)
   ├─ F6 FallDetector   → 알람 source="camera" + confidence
   └─ F7 NoMotionDetector → 알람 source="no_motion"
```
- F6·F7 모두 **같은 pose 키포인트**를 쓰고 **규칙으로 판정**한다.
- F7은 별도 모델·학습 없이 계산만 한다. 학습 검토는 F6(누운 자세 인식)에만 해당한다.
- 상태 값: `none`(사람 없음) / `standing` / `sitting` / `falling` / `lying`.

### 판정 규칙
모든 임계값은 `pi/app/config.py`의 설정값으로 둔다 (코드에 숫자 하드코딩 금지). 값은 실측 후 정한다.

**F6 낙상**
- 머리 하강 **속도와 높이는 픽셀이 아니라 사람 bbox 높이 대비 비율**로 판정한다 (사람이 멀고 가까운 것에 영향 안 받게).
  - 예: 머리(코·눈·귀 중 신뢰도 높은 점) y의 변화량 / bbox 높이, 단위 시간당.
- 몸통 각도: 어깨 중점 → 엉덩이 중점 벡터와 수직선의 각도. 수평에 가까우면 누운 자세 후보.
- 누운 상태 지속 시간: 빠른 하강 후 누운 자세가 일정 시간 이상 이어지면 낙상 확정.
- 설정값: 하강 속도 비율, 몸통 각도, 누운 상태 지속 시간, 키포인트 최소 신뢰도.

**F7 무움직임**
- **로봇이 정지 상태일 때만** 이동량을 누적한다. 로봇이 움직이면 카메라도 같이 움직여 키포인트가 흔들리므로
  ESP32 `status.mode`가 **이동 중인 모드**이면 누적을 멈추고 초기화한다.
  - 이동 중인 모드 목록은 설정값(`pi/app/config.py`)으로 둔다. 지금 프로토콜의 이동 모드는 `walking`.
    `approaching`(사용자에게 다가가기) 등 이동 모드가 [serial-protocol.md](serial-protocol.md)에 추가되면 이 목록에도 넣는다.
  - ESP32 `status`가 끊겨 모드를 모를 때(`esp32_ok=false`)는 로봇이 움직이는지 알 수 없으므로 누적하지 않는다.
- 키포인트는 **사람 bbox 크기로 정규화**한 뒤 프레임 간 이동량을 계산한다 (신뢰도 낮은 점 제외).
- **"사람 없음(none)"과 "움직임 없음"을 구분**한다. 사람이 화면 밖이면 누적을 멈추고 F7 알람을 내지 않는다.
- N분 동안 정규화 이동량이 임계값 미만이면 알람. 설정값: N(분), 이동량 임계값, 사람 없음 허용 시간, 이동 중인 모드 목록.

### 모델 선택 (Hailo 기준)
- "YOLO11n-pose, 입력 320 / 의심 시 640"은 CPU 추론 기준의 선택이었다. Hailo-8L을 쓰므로 **s·m 크기도 후보**로 둔다.
- 낙상 감지는 초당 5~10프레임이면 충분 → 속도에 여유가 있으면 더 정확한 모델을 고른다.
  선택 기준: **초당 10프레임 이상인 모델 중 누운 자세 인식이 가장 좋은 것**.
- 제약:
  - AI HAT+ 13T = **Hailo-8L**. `.hef`는 반드시 **hailo8l 대상**으로 컴파일된 것만 쓴다 ([setup.md](setup.md) 2-3-1).
  - 모델이 커서 칩에 다 안 들어가면 여러 번 나눠 실행(context switch)되어 속도가 크게 떨어질 수 있다 → 벤치마크로 확인.
  - 입력 크기는 `.hef` 컴파일 때 고정된다. 320/640 전환에는 `.hef` 두 개가 필요하므로 **기본은 640 하나**.
  - 큰 모델일수록 Hailo 전력이 늘어 X1200 배터리 사용 시간이 줄어든다 → 벤치마크에 전력·발열도 기록.
  - YOLO11·YOLO26은 Hailo-8L용 기성 `.hef`가 없을 수 있어 **DFC 변환**이 필요하다.
    DFC는 x86 Linux 별도 환경에서 돌리고, 레포 공용 conda(`pd-dog`)와 섞지 않는다.

### 진행 순서
1. Hailo Model Zoo의 **hailo8l용 기성 pose 모델**(yolov8s_pose, yolov8m_pose 등)로 Pi에서 Hailo 추론을 붙인다.
2. 모델별 **초당 프레임 수, 지연 시간, 누운 자세 인식 정도**를 벤치마크 → [benchmarks.md](benchmarks.md).
   초당 10프레임 이상 중 가장 정확한 모델을 고른다.
3. F6·F7을 규칙 기반으로 구현한다.
4. 학습 전에 **카메라 각도, 사용자와의 거리(2~3m), 입력 해상도 조정**으로 누운 자세 인식률을 먼저 확인한다.
5. 그래도 누운 자세를 자주 놓치면 개선을 검토한다. 두 안을 비교한 뒤 결정:
   - **pose 모델 파인튜닝**: 키포인트 17개 라벨이 필요해 작업량이 크다.
   - **"넘어진 사람" 검출 모델을 보조로 추가**: bbox 라벨만 필요해 더 쉽다.
   - 어느 쪽이든 hailo8l용 `.hef` 변환(DFC)이 필요하다.
