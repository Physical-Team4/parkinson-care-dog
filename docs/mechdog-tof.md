코드 파일: `mainboard.py` (보드에는 `main.py`로 올림), `tof_test.py`, `original_main.py`(원본 앱 조종 코드)

## 1. 전체 기능 요약

| 기능 | 동작 |
|---|---|
| 앱 블루투스 조종 | 원본 코드 그대로 유지 (`original_main.py`) |
| 리듬 큐잉 시작/정지 | 터치 센서를 터치 (다시 터치하면 정지) / 블루투스 `CMD\|7\|1\|$` 시작, `CMD\|7\|0\|$` 정지 |
| 박수 소리 | MP3 모듈이 박자마다 박수 파일(25번) 재생 |
| 뒤 장애물 멈춤 | 리듬 큐잉이 아닐 때, 뒤 20cm 안에 물체가 있으면 뒤로 걷기를 멈춤 |
| 사람 따라오기 | 리듬 큐잉 중, 뒤 사람과의 거리에 따라 보폭 조절 / 놓치면 멈춰서 대기 |

- 리듬 큐잉 중 앱으로 다른 동작을 시키면 리듬 큐잉은 자동으로 멈추고 그 명령이 실행됨
- 장애물 회피 모드나 자동 균형 모드가 켜져 있으면 리듬 큐잉이 시작되지 않음

## 2. 눈(LED) 색깔 의미

눈은 앞쪽 초음파 센서의 LED를 사용함.

### 리듬 큐잉 중

| 상황 | 눈 | 동작 |
|---|---|---|
| 시작 직후, 뒤에 사람 없음 | 주황 깜빡임 | 제자리에서 대기 (박수는 계속) |
| 사람이 1.5m 안에 0.7초 이상 잡힘 | 초록 | 걷기 시작 |
| 사람이 50cm 이내 | 초록 | 원래 보폭으로 걷기 |
| 사람이 50cm ~ 1.2m | 초록 | 멀어질수록 보폭을 줄여 천천히 걷기 |
| 1.5m보다 멀거나 안 잡힘이 1초 이상 | 주황 깜빡임 | 멈춰서 기다림 |
| 10초 이상 계속 못 찾음 | 꺼짐 | 리듬 큐잉 종료 |
| 터치로 정지 | 꺼짐 | 멈추고 기본 자세 |

### 리듬 큐잉이 아닐 때

| 상황 | 눈 |
|---|---|
| 뒤 20cm 안에 물체 있음 | 빨강 (뒤로 걷기 막힘) |
| 뒤 물체가 사라짐 | 꺼짐 |

### 원본 앱의 장애물 회피 모드 (앞 초음파 센서 기준)

| 앞 거리 | 눈 | 동작 |
|---|---|---|
| 10 미만 | 빨강 | 뒤로 3초 |
| 10 ~ 40 | 노랑 | 방향 틀기 5초 |
| 40 이상 | 보라 | 직진 |
| 모드 종료 | 파랑 | 정지 |

## 3. 포트와 I2C 통로 번호

**보드에 적힌 포트 번호와 코드의 통로 번호(`IIC(1)`, `IIC(2)`)는 다를 수 있음.** 헷갈리면 항상 `scan()`으로 확인할 것.

```python
import Hiwonder_IIC
print("bus1:", Hiwonder_IIC.IIC(1).scan())
print("bus2:", Hiwonder_IIC.IIC(2).scan())
```

| 장치 | 주소 | 확인된 통로 | 비고 |
|---|---|---|---|
| 자세 센서(IMU, 보드 내장) | 106 (0x6A) | 1 | 항상 보임 |
| 앞 초음파 센서(눈) | 119 (0x77) | 1 | 항상 보임 |
| 뒤 ToF 센서 VL53L1X | 41 (0x29) | 1 | 코드는 1, 2번 통로 자동 탐색 |
| WonderEcho 음성 모듈 | 52 (0x34) | 2 | 보드 1번 포트에 꽂았을 때 |
| MP3 모듈 | - | 블록에서 "포트 2" | scan에 잘 안 잡힘, 코드는 자동 탐색 |
| 터치 센서 | - | 3번 포트 (IO33) | I2C 아님, 여기에 I2C 장치 꽂지 말 것 |

- `OSError: [Errno 19] ENODEV` = 그 주소에 장치가 없다는 뜻. 연결이 빠졌거나, 다른 장치 주소로 명령을 보내고 있는 것
- 검사(`scan`)가 끝나지 않고 멈추면 통신선이 꼬였거나(SDA/SCL), 전원이 안 들어간 장치가 선을 붙잡고 있는 것

## 4. 뒤 ToF 거리 센서 (VL53L1X, CJMCU-531) 주의사항

### 연결

- 6핀 중 **VCC, GND, SCL, SDA 4개만** 연결. GPIO1, XSHUT은 비워둠
- 기판에 전압 조절 칩과 저항이 있어서 **MechDog 포트의 5V를 그대로 연결해도 됨**
- **선 색깔을 믿지 말 것.** 연결 케이블의 빨간 선이 VCC가 아닐 수 있음. 반드시 포트 핀 순서와 센서 글자를 이름끼리 맞출 것
- VCC와 GND가 바뀌면 센서가 망가질 수 있음. 전원 켜기 전에 한 번 더 확인
- 연결 정보 (작업 후 채워 넣기): 포트 ___번 / VCC = ___색, GND = ___색, SCL = ___색, SDA = ___색

### 납땜

- **납땜 없이 헤더핀만 꽂으면 접촉이 안 됨.** 실제로 납땜 전에는 센서가 전혀 안 잡혔음
- 헤더핀 방향: **짧은 쪽을 센서 없는 면(뒷면)에서 꽂아 넣고**, 플라스틱 받침이 뒷면에 닿게 함. 긴 쪽이 뒷면으로 나와 점퍼선을 꽂음
- 납땜은 센서 창이 있는 면으로 살짝(약 1mm) 튀어나온 핀 끝에서 함
- 인두를 핀과 구멍 둘레 금속 테두리에 동시에 대고 2~3초 안에 끝내기
- 잘된 납땜은 반짝이는 원뿔 모양. 동그란 공처럼 맺히면 다시 데우기
- **모든 핀이 납땜됐는지 확인할 것.** 실제로 GND 하나가 빠져서 센서가 안 켜졌었음
- 옆 핀끼리 납이 이어지지 않게 주의 (특히 VCC-GND)
- 납땜 중 센서가 뜨거워지는 건 정상. **전원을 켰을 때 뜨거워지면 즉시 전원을 끄고** 연결 확인

### 보호 필름

- 납땜할 때는 센서 창 보호 필름을 붙여두고 (연기, 송진 방지)
- **납땜이 끝나면 반드시 필름을 뗄 것.** 필름이 있으면 레이저가 반사돼서 아무것도 없어도 가까운 물체가 있는 것처럼 측정됨 (실제로 이것 때문에 뒤로 걷기가 계속 막혔음)
- 센서 창에 송진이 묻었으면 면봉에 소독용 알코올을 살짝 묻혀 닦기

### 테스트

- `tof_test.py`를 올리면 센서를 찾고 30초 동안 거리를 0.2초마다 출력함
- 정상 결과 예: `bus 1 devices: [41, 106, 119]` → `ToF OK on bus 1 access mode: mem16` → `distance: 225 mm`
- 측정 범위 약 5mm ~ 4m, 가만히 있을 때 흔들림 ±5mm 정도
- 이 센서는 Hiwonder 제품이 아니라서 센서 설정 코드(드라이버)가 `mainboard.py` 안에 들어 있음. 전원은 MechDog 켜질 때 같이 켜지고, 설정은 켜질 때 한 번 자동으로 함

## 5. MP3 모듈과 박수 소리

- 사용법: `mp3 = Hiwonder_IIC.MP3(Hiwonder_IIC.IIC(통로))`, `mp3.volume(0~30)`, `mp3.play(번호)`, `mp3.pause()`
- 기본 곡 번호 16~24 (16 Street Dance, 17 Gangnam Style 등), 박수 파일은 25번(`0025.mp3`)으로 추가
- 박수 파일 조건: **0.3초 이하로 짧게, 앞쪽 무음 제거** (무음이 있으면 박자보다 늦게 들림)
- 카드에 넣는 법: MechDog 전원 끄기 → 모듈에서 microSD 빼기 → 카드 리더로 노트북 연결 → 기존 파일과 같은 폴더, 같은 이름 형식으로 복사 → 안전하게 꺼내기 → 다시 꽂기
- 기존 파일은 지우거나 이름을 바꾸지 말 것
- WonderEcho 스피커의 내장 문구는 길어서 메트로놈용으로 부적합 (짧은 간격으로 재생하면 계속 끊겨서 소리가 안 남)
- 박수 소리 파일은 팀 저장소에 올릴 수 있는 라이선스인지 확인

## 6. 걷기와 동작 관련 주의사항

- `mechdog.move(보폭mm, 방향)`: 첫 번째 값은 속도가 아니라 **보폭(mm)**. 음수면 뒤로
- `mechdog.set_gait_params(들기ms, 착지ms, 다리높이mm)`: 걸음 주기 설정. 기본값 150, 500, 40
- 리듬 큐잉은 BPM으로 걸음 주기를 계산함 (50 BPM = 1200ms = 들기 150 + 착지 1050)
- **들기 시간(lift)을 길게 하면 뒤뚱거림.** 박자 조절은 착지 시간으로 할 것. 다리 높이도 낮을수록 안정적
- 실제 걷는 속도 = 보폭 × BPM. 박자는 고정하고 보폭으로 걸음 크기를 조절
- 동작 이름 철자 주의: `sit_dowm`(dowm이 맞음). 틀리면 `err:except`
- 사용 가능한 동작: stand_four_legs, sit_dowm, go_prone, stand_two_legs, handshake, scrape_a_bow, nodding_motion, stretch_oneself, press_up, boxing, pee, left_foot_kick, right_foot_kick, rotation_pitch, rotation_roll
- `run_status busy:1` = 이전 동작이 끝나기 전에 명령이 겹침. 명령 사이에 기다리는 시간을 늘릴 것

### 블록 코딩에서 겪은 함정

- **"Set MechDog Forward ○mm" 블록은 걷기가 아니라 몸통 이동.** 현재 자세에서 계속 더해지므로 여러 번 쓰면 몸이 쏠려서 뒤집힘
- 걷기 블록은 **"Set MechDog's forward stride to ○mm"**
- 보폭 0은 "멈춤"이 아니라 "제자리 걸음"이 될 수 있음
- **"멈추기" 블록은 MechDog가 아니라 프로그램 자체를 멈춤.** 그 아래 블록(노래 끄기 등)이 실행되지 않음
- 블록의 파이썬 코드는 블록 화면 오른쪽 코드 창이나 업로드 로그의 `fp.write(...)`에서 확인 가능

## 7. 코드 업로드 주의사항

- 보드에는 `main.py` 하나만 있고, **마지막에 올린 것이 이전 것을 덮어씀** (블록이든 파이썬이든 동일)
- 저장소에서는 `mainboard.py`로 관리하고, 보드에 올릴 때 `main.py`가 되게 함
- 올리기 전에 기존 코드는 꼭 저장소나 노트북에 백업. 원본은 `original_main.py`
- **WonderCode는 한글을 지워버림.** 주석과 출력 문구는 영어로 작성
- WonderCode 업로드 전, 편집창에 다른 예제가 열려 있지 않은지 확인 (예제가 대신 올라간 적 있음)
- 부분 수정보다 **전체를 Ctrl+A로 지우고 통째로 붙여넣기**가 안전함 (들여쓰기 오류, SyntaxError 방지)
- 파이썬은 줄 앞 공백(들여쓰기) 한 칸만 달라도 오류가 남
- mpremote로 올리기: `mpremote connect COM3 cp mainboard.py :main.py` (COM 번호는 장치 관리자의 USB-SERIAL CH340)
- 보드에서 코드 가져오기: `mpremote connect COM3 cp :main.py main.py`

## 8. 연결과 전원 문제

- USB를 꽂으면 보드가 재시작되며 기본 자세로 한 번 움찔하는 건 정상
- **계속 반복해서 꿈틀거리면 전원 부족.** 배터리를 충전하고 전원 스위치를 켠 상태로 USB 연결
- 저절로 나는 경보음 = 배터리 부족 경고 가능성이 높음
- PC가 MechDog를 못 찾으면: 장치 관리자에서 `USB-SERIAL CH340` 포트 확인 / 충전 전용 케이블이 아닌지 확인 / 다른 프로그램이 포트를 쓰고 있지 않은지 확인
- `Guru Meditation`이나 `EXCCAUSE`가 찍히며 재시작 = 펌웨어 내부 오류. 명령이 겹치거나 배터리가 부족할 때 잘 남

## 9. 주요 설정값 (`mainboard.py` 위쪽)

| 설정 | 현재값 | 의미 |
|---|---|---|
| `RHYTHM_BPM` | 50 | 박자 |
| `RHYTHM_STRIDE` | 25 | 기본 보폭(mm). 너무 작으면 제자리처럼 보임 |
| `CLAP_TRACK` | 25 | 박수 파일 번호 |
| `RHYTHM_VOLUME` | 25 | MP3 볼륨 (0~30) |
| `TOUCH_DEBOUNCE_MS` | 500 | 연속 터치 무시 시간 |
| `TOF_BUS` | 1 | 뒤 센서를 먼저 찾을 통로 |
| `REAR_STOP_MM` | 200 | 뒤 장애물 멈춤 거리 |
| `REAR_STOP_ALL` | False | True면 앞으로 걸을 때도 뒤 장애물에 멈춤 |
| `FOLLOW_NEAR_MM` | 500 | 이 거리 이내면 원래 보폭 |
| `FOLLOW_FAR_MM` | 1200 | 이 거리면 최소 보폭 |
| `LOST_MM` | 1500 | 이보다 멀면 사람 놓침 |
| `RHYTHM_STRIDE_MIN` | 10 | 최소 보폭 |
| `LOST_CONFIRM_MS` | 1000 | 이만큼 놓치면 멈춤 |
| `FOUND_CONFIRM_MS` | 700 | 이만큼 잡히면 다시 걷기 |
| `LOST_END_MS` | 10000 | 이만큼 놓치면 리듬 큐잉 종료 |
| `BEAT_WHILE_WAITING` | True | 기다리는 동안에도 박수 소리 유지 |
| `DEBUG_REAR` | True | 뒤 거리 출력 (테스트 끝나면 False로) |

`DEBUG_REAR = True`일 때 출력 예: `rear: 245 raw: 243 age: 80 blocked: False dir: 0`
(rear = 판단에 쓰는 거리, raw = 마지막 측정값, age = 마지막 측정 후 시간, blocked = 뒤 막힘 여부, dir = 앱 걷기 방향 6~8이 뒤로)
