# MechDog 리듬 큐잉 작업 노트

작업하면서 직접 부딪히고 알아낸 내용과 주의사항을 정리한 문서입니다.
코드 파일: `esp32/mainboard.py` (원본 앱 조종 코드 포함, 보드에는 `main.py`로 올림), 박수 소리 `esp32/sounds/0025.mp3`
뒤 거리 센서(사람 따라오기, 뒤 장애물 멈춤)와 I2C 포트 내용은 [mechdog-tof.md](mechdog-tof.md) 참고.

---

## 1. 전체 기능 요약

| 기능 | 동작 |
|---|---|
| 앱 블루투스 조종 | 원본 코드 그대로 유지 (`mainboard.py`) |
| 리듬 큐잉 시작/정지 | 터치 센서를 터치 (다시 터치하면 정지) / 블루투스 `CMD\|7\|1\|$` 시작, `CMD\|7\|0\|$` 정지 |
| 박수 소리 | MP3 모듈이 박자마다 박수 파일(25번) 재생 |
| 뒤 장애물 멈춤, 사람 따라오기 | 뒤 ToF 센서 사용 → [mechdog-tof.md](mechdog-tof.md) |

- 리듬 큐잉 중 앱으로 다른 동작을 시키면 리듬 큐잉은 자동으로 멈추고 그 명령이 실행됨
- 장애물 회피 모드나 자동 균형 모드가 켜져 있으면 리듬 큐잉이 시작되지 않음

---

## 2. 눈(LED) 색깔 의미

눈은 앞쪽 초음파 센서의 LED를 사용함.
리듬 큐잉 중 색깔(주황 깜빡임 = 사람 기다림, 초록 = 따라오는 중)은 [mechdog-tof.md](mechdog-tof.md) 2번 참고.

### 원본 앱의 장애물 회피 모드 (앞 초음파 센서 기준)

| 앞 거리 | 눈 | 동작 |
|---|---|---|
| 10 미만 | 빨강 | 뒤로 3초 |
| 10 ~ 40 | 노랑 | 방향 틀기 5초 |
| 40 이상 | 보라 | 직진 |
| 모드 종료 | 파랑 | 정지 |

## 3. MP3 모듈과 박수 소리

- 사용법: `mp3 = Hiwonder_IIC.MP3(Hiwonder_IIC.IIC(통로))`, `mp3.volume(0~30)`, `mp3.play(번호)`, `mp3.pause()`
- 기본 곡 번호 16~24 (16 Street Dance, 17 Gangnam Style 등), 박수 파일은 25번(`0025.mp3`)으로 추가
- 박수 파일 조건: **0.3초 이하로 짧게, 앞쪽 무음 제거** (무음이 있으면 박자보다 늦게 들림)
- 카드에 넣는 법: MechDog 전원 끄기 → 모듈에서 microSD 빼기 → 카드 리더로 노트북 연결 → 기존 파일과 같은 폴더, 같은 이름 형식으로 복사 → 안전하게 꺼내기 → 다시 꽂기
- 기존 파일은 지우거나 이름을 바꾸지 말 것
- WonderEcho 스피커의 내장 문구는 길어서 메트로놈용으로 부적합 (짧은 간격으로 재생하면 계속 끊겨서 소리가 안 남)
- 박수 소리 파일은 팀 저장소에 올릴 수 있는 라이선스인지 확인

## 4. 걷기와 동작 관련 주의사항

- `mechdog.move(보폭mm, 방향)`: 첫 번째 값은 속도가 아니라 **보폭(mm)**. 음수면 뒤로
- `mechdog.set_gait_params(들기ms, 착지ms, 다리높이mm)`: 걸음 주기 설정. 기본값 150, 500, 40
- 리듬 큐잉은 BPM으로 걸음 주기를 계산함 (50 BPM = 1200ms = 들기 150 + 착지 1050)
- **들기 시간(lift)을 길게 하면 뒤뚱거림.** 박자 조절은 착지 시간으로 할 것. 다리 높이도 낮을수록 안정적
- 실제 걷는 속도 = 보폭 × BPM. 박자는 고정하고 보폭으로 걸음 크기를 조절
- 동작 이름 철자 주의: `sit_dowm`(dowm이 맞음). 틀리면 `err:except`
- 사용 가능한 동작: stand_four_legs, sit_dowm, go_prone, stand_two_legs, handshake, scrape_a_bow, nodding_motion, stretch_oneself, press_up, boxing, pee, left_foot_kick, right_foot_kick, rotation_pitch, rotation_roll
- `run_status busy:1` = 이전 동작이 끝나기 전에 명령이 겹침. 명령 사이에 기다리는 시간을 늘릴 것

### 블록 코딩에서 겪은 함정

- **"Set MechDog Forward ○mm" 블록은 걷기가 아니라 몸통 이동.** 현재 자세에서 계속 더해지므로 여러 번 쓰면 몸이 쏠려서 뒤집힘
- 걷기 블록은 **"Set MechDog's forward stride to ○mm"**
- 보폭 0은 "멈춤"이 아니라 "제자리 걸음"이 될 수 있음
- **"멈추기" 블록은 MechDog가 아니라 프로그램 자체를 멈춤.** 그 아래 블록(노래 끄기 등)이 실행되지 않음
- 블록의 파이썬 코드는 블록 화면 오른쪽 코드 창이나 업로드 로그의 `fp.write(...)`에서 확인 가능

## 5. 코드 업로드 주의사항

- 보드에는 `main.py` 하나만 있고, **마지막에 올린 것이 이전 것을 덮어씀** (블록이든 파이썬이든 동일)
- 저장소에서는 `mainboard.py`로 관리하고, 보드에 올릴 때 `main.py`가 되게 함
- 올리기 전에 기존 코드는 꼭 저장소나 노트북에 백업. 원본 앱 조종 코드는 `mainboard.py`에 들어 있음
- **WonderCode는 한글을 지워버림.** 주석과 출력 문구는 영어로 작성
- WonderCode 업로드 전, 편집창에 다른 예제가 열려 있지 않은지 확인 (예제가 대신 올라간 적 있음)
- 부분 수정보다 **전체를 Ctrl+A로 지우고 통째로 붙여넣기**가 안전함 (들여쓰기 오류, SyntaxError 방지)
- 파이썬은 줄 앞 공백(들여쓰기) 한 칸만 달라도 오류가 남
- mpremote로 올리기: `mpremote connect COM3 cp mainboard.py :main.py` (COM 번호는 장치 관리자의 USB-SERIAL CH340)
- 보드에서 코드 가져오기: `mpremote connect COM3 cp :main.py main.py`

## 6. 연결과 전원 문제

- USB를 꽂으면 보드가 재시작되며 기본 자세로 한 번 움찔하는 건 정상
- **계속 반복해서 꿈틀거리면 전원 부족.** 배터리를 충전하고 전원 스위치를 켠 상태로 USB 연결
- 저절로 나는 경보음 = 배터리 부족 경고 가능성이 높음
- PC가 MechDog를 못 찾으면: 장치 관리자에서 `USB-SERIAL CH340` 포트 확인 / 충전 전용 케이블이 아닌지 확인 / 다른 프로그램이 포트를 쓰고 있지 않은지 확인
- `Guru Meditation`이나 `EXCCAUSE`가 찍히며 재시작 = 펌웨어 내부 오류. 명령이 겹치거나 배터리가 부족할 때 잘 남

## 7. 리듬 큐잉 설정값 (`mainboard.py` 위쪽)

| 설정 | 현재값 | 의미 |
|---|---|---|
| `RHYTHM_BPM` | 50 | 박자 |
| `RHYTHM_STRIDE` | 25 | 기본 보폭(mm). 너무 작으면 제자리처럼 보임 |
| `CLAP_TRACK` | 25 | 박수 파일 번호 |
| `RHYTHM_VOLUME` | 25 | MP3 볼륨 (0~30) |
| `TOUCH_DEBOUNCE_MS` | 500 | 연속 터치 무시 시간 |

거리 센서 관련 설정값(`TOF_BUS`, `FOLLOW_*`, `LOST_*` 등)은 [mechdog-tof.md](mechdog-tof.md) 5번 참고.
